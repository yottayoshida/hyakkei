# テンプレート作成ガイド

Hyakkei のテンプレートは `dashboard.json` です。元データそのものではなく、データソースの名前、列名、集計条件、グラフ、レイアウトを保存するため、同じ列構成の定型レポートを繰り返し作れます。

## 形式の違い

テンプレートとして保存するのは authoring `Dashboard` です。`sources` と `queries` は
参照情報・SQL・列指定を持ちますが、元データの行は持ちません。一方、配布用HTMLや
フォルダーZIPは `bake()` 済みの `BakedDashboard` で、表示に必要な集計済み行を
`charts[].rows` に含みます。配布物をテンプレートとして再編集するのではなく、元の
`dashboard.json` を開いてデータを差し替えてください。

## 作る

1. 個人情報を含まない代表データで、CSV または `.xlsx` を読み込みます。
2. 「このデータを集計」で、用途に必要な単位・値・条件を設定します。
3. 「グラフ化」で見せ方を選び、タイトルとレイアウトを調整します。
4. 「保存」を選び、`dashboard.json` を分かる名前で保管します。

## 使う

1. ヘッダーの「開く」からテンプレートの `dashboard.json` を選びます。
2. 求められたときは、テンプレート作成時と同じ列構成の元データを選びます。
3. プレビューで集計値と見出しを確認し、必要ならタイトル・条件・レイアウトを更新します。
4. 作業用には「保存」、配布用には「配布用HTML」を選びます。

## 公開前の確認

- `dashboard.json` にはセル値を保存しませんが、元データのファイル名・シート名・列名・SQL の集計条件を保存します。機密情報が名前に含まれないようにします。
- 配布用 HTML には、表示するグラフを再現するための集計済みの行が入ります。データの公開可否と共有先を確認します。
- テンプレートの列名を変える場合は、クエリとグラフの列指定も更新してから保存し直します。

## 検証ゲートと互換性

保存前のCIでは、次の順に確認します。

1. schema validation: authoring / baked の必須フィールド、型、バージョン。
2. reference validation: source、query、chart、layout のIDと列指定が解決できること。
3. guideline validation: ルールに該当する警告がないこと（ルールの引用元も保存します）。

将来のバージョンで追加された未知のフィールドは、編集対象でない限り読み込み・保存時に
保持する方針です。独自拡張を加える場合は、既存キーを上書きせず、schema/referenceの
テストと一緒に追加してください。

## 出典の記録

公開データを使うテンプレートでは、`sources[].ref` にファイル名だけでなく、公開元URL・
表番号・調査年を記録し、変換したCSV/JSONのSHA-256を説明文またはリポジトリの
provenanceファイルに残します。Hyakkeiの3つの公開サンプルの実例は
[`docs/gallery-data.md`](./gallery-data.md) にあります。取得元の利用条件と、配布用HTMLに
集計済みデータが含まれることを、共有前に確認してください。

## Git で管理する場合

`dashboard.json` はレビュー可能なテキストです。テンプレートとその代表データの説明を同じ変更に含め、変更後は実際に開いてグラフと値を確認します。ブラウザで完結するため、静的ホスティング（GitHub Pages、オブジェクトストレージ、通常のファイルサーバー）でも配布できます。
