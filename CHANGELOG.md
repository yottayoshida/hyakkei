# Changelog

Day-by-day development log for hyakkei, from repository bootstrap through the current M1 milestone. Each entry summarizes the PRs merged that day — what changed and why, not a line-by-line diff. See individual PR descriptions and ADRs under `docs/adr/` for full detail.

This project has not yet reached a versioned release; entries are grouped by date rather than by semver tag.

## 2026-08-04

- **feat(schema,core): add meta provenance fields and the dashboard footer (#124) (#137)** — The guidebook's p41 lists 更新日, 出典 and 要約 among the things a dashboard states about itself, and the schema could express none of them; `meta.updatedAt`, `meta.sourceNote` and `meta.summary` now exist as optional fields and a new footer draws them below the grid. Two placements differ from what [ADR-0017](docs/adr/0017-v1-is-agent-generated-dashboards.md) Decision 7's prose implies, and [ADR-0019](docs/adr/0019-guidebook-do-side-fields-and-dashboard-chrome.md) records why. `updatedAt` is `format:"date"` and is deliberately not `sourceDataAsOf`: p41 lists "when this was updated" and "as of when the data is" as separate items, so folding them together would misreport one of the two. `sourceNote` is per dashboard rather than per source, because `BakedDashboard` declares `ForbidFields("sources")` — a per-source note has no structural path into the artifact a third party opens, which is this requirement's only audience. `RenderModel.footer` carries a discriminated union whose branch is chosen in the normaliser rather than at render time, and that is not a style preference: authoring-side `meta.generatedAt` has no type on it, so `null` and numbers both pass, and a render-time check would narrow on a value that can be neither — with the footer sitting outside the per-tile `try`/`catch` that contains every other failure in this renderer, one bad value would take the whole dashboard down instead of one card. `normalizeAuthoring` can only read `BaseMeta`, which makes the render-time alternative uncompilable rather than merely discouraged. `schemaFieldsOwed` in `docs/guidebook-coverage.md` goes 4 → 1 and is now derived from the schemas instead of hand-typed, since editing the count and the documents together would otherwise have turned all seventeen mirrors green whether or not a field reached the schema; a case asserting that the derivation descends into `Chart`'s intersect arms travels with it, because the four entries it derives from cannot distinguish that read from one that ignores `allOf` — the only `Chart` entry is the field this change does not add. The three fields that landed are recorded under a new `supported` status that moves no headline figure, so the 9 guaranteed / 0 known defects claim form is unaffected. `Chart.altText` remains owed and belongs on `Chart` rather than `ChartOptions`, whose unknown-key rejection is pinned and would make such a document fail to open in an older hyakkei; issue #124 stays open for it. Three defects here were found only by opening a real browser and are invisible to jsdom: the provenance line clipped off screen, 出典 printed twice, and the separator falling to the start of a wrapped line. `download-filename.ts` also switches its hand-written bidi-control list to `\p{Bidi_Control}`, the form the new `display-text.ts` reached independently; the two sets are the same twelve code points, verified by walking every Unicode scalar value.
- **docs: state that piping a push gate discards its exit code (#138)** — `CLAUDE.md` required running `pnpm run lint` and `pnpm run format` before a push but said nothing about how to observe the result, and piping a gate through another command returns that command's exit status — so a failing gate reads as green and an `&&` chain continues past it. This has now happened twice here: the commit before #132 was pushed unformatted for exactly this reason, and on 2026-08-04 the same shape hid a failing `typecheck` on the #124 branch, caught only because pnpm's own `ELIFECYCLE` line was still in the output, which is luck rather than a check. The rule that already existed asked for execution but not for observation, and that gap is what both instances went through. Carries a deletion condition, per the workspace's sunset rule: it goes away if a pre-push hook ever runs these mechanically.
- **fix(e2e): give every project the CI retry budget, not just webkit (#140) (#141)** — `retries: isCI ? 1 : 0` moves from the webkit project to the top level. Issue #97 had placed it on webkit because that is where three consecutive contention timeouts had been observed, but the cause it absorbs — DuckDB-WASM worker spin-up racing the 2 concurrent workers that Playwright's default `workers: "50%"` allows on a 4-vCPU runner — is browser-independent, so chromium and firefox carried the same exposure with no retry budget at all. Chromium then hit it twice on this same day, on two different spec files, both times on the same `データワークスペース` heading assertion and both times on a commit that was green: #137, and then #139, which added five CHANGELOG lines and touched no source at all — a change that cannot have altered any timing, which is the clearest evidence available that the variance is entirely runner-side. Each red run cost a full rerun before its result could be trusted, and had to be investigated to rule out a real regression, which is the actual cost rather than the wall clock. This is a mitigation and says so: a readiness gate that waits once for the WASM worker before any spec runs is the only option that removes the race, and it remains open on [#140](https://github.com/yottayoshida/hyakkei/issues/140) as the real fix. Regression detection is unchanged — #97's `github` reporter turns a retry-then-pass into an `::error` annotation and is configured at the top level, so it already covered the widened scope without further work. The webkit comment's substance is preserved rather than dropped: the corrected 4-vCPU/2-worker analysis and all four rejected alternatives moved up with the setting, and only the part asserting webkit-specific scope was rewritten. Verified from Playwright's resolved configuration rather than from its source text — `retries` is 1 for all three projects under `CI=1` and 0 for all three without it, with collection still at 282 tests, so the edit did not silently shrink the suite. The first CI run after the change consumed no retry, which makes it evidence that nothing broke rather than evidence that the retry works; that can only be observed the next time contention actually bites.

## 2026-08-02

- **docs: amend the MCP transport gate for protocol revision 2026-07-28 (#135)** — MCP replaced its core protocol on 2026-07-28 — protocol-level sessions and the `initialize` handshake removed, a mandatory `server/discover`, per-request protocol version and capabilities in `_meta`, `ping` / `logging/setLevel` / SSE resumability gone — and **no decision in this repository changes**, which is the finding rather than the absence of one. MCP Apps runs on its own release track: its specification is still the 2026-01-26 revision, and the `extensions` framework the new core introduces is precisely the mechanism that keeps it there, so `ui://`, `_meta.ui.resourceUri`, the sandboxed iframe and the `postMessage` dialect are untouched and the transport gate's two-channel conclusion survives intact. [ADR-0017](docs/adr/0017-v1-is-agent-generated-dashboards.md) Decision 3's stated reason for making the CLI the core — confining MCP specification churn to a thin adapter — is what absorbed this, and it can be checked rather than asserted: the churn landed entirely inside a component that does not exist yet, since the repository declares no MCP dependency and `packages/` is still app/core/export/schema. What the amendment records is therefore the contract the first line of that component will be written against: `server/discover` is mandatory and is where a server advertises `capabilities.extensions` now that there is no `initialize` to negotiate in; every result carries `resultType`; `ttlMs` and `cacheScope` are required on the four list methods **and on `resources/read`**, which is the call that serves the `ui://` bundle; and Roots, Sampling and Logging are deprecated, none of which this shape needs. One live hazard is written down rather than resolved: the TypeScript SDK split at v2 on 2026-07-27 into `@modelcontextprotocol/core` / `server` / `client` / `express` / `fastify`, only v2 speaks `2026-07-28`, and `@modelcontextprotocol/ext-apps@1.7.5` still peers on `@modelcontextprotocol/sdk: ^1.29.0` — the SDK side has already restored the v1 `Protocol` root export for exactly this consumer (server v2.0.0, PR #2501), so the range is expected to move and must be looked up at start rather than remembered. Two statements in the spike had also gone stale for reasons unrelated to the revision, both found in the `ext-apps#671` thread: the re-test trigger named a tracker that cannot resolve it — on 2026-07-31 that thread's most active investigator stated that host-rendering triage does not happen in the spec and SDK repository and moved the writeup to [`anthropics/claude-ai-mcp#165`](https://github.com/anthropics/claude-ai-mcp/issues/165), leaving "when #671 closes" a condition that can never fire — and "no server-side or content-side change can fix it" proved too broad, since a 36-render measurement the same day found a second failure with the same visible symptom that is entirely ours: a **wrong** `_meta.ui.domain` mounted the iframe in 0 of 8 renders while **omitting** it mounted in 10 of 10, and a stale cached `ui://` URI after a rebuild raises the same "Unable to reach" error, making one symptom cover three causes. A same-class scan over every `*.md` — by string and independently by claim — found five more instances outside the spike, all fixed here: ROADMAP's Known constraint carried both stale statements one line from the release criteria and is corrected in place as a live planning document, while ADR-0017 gets a dated read-forward note with its body left unedited, per the convention `docs/adr/0016` states as "Original text below is unedited." The MCP mention inside this file's released #125 entry is deliberately left alone for the same reason.

## 2026-07-28

- **fix(core): resolve chart color roles from the guidebook's published role layer (#131)** — Chart colors now take their _role assignment_ from the guidebook's own [カラーパレットの使い方](https://www.digital.go.jp/resources/dashboard-guidebook/color-palette) page rather than inferring it from `@digital-go-jp/design-tokens`, which carries primitive ramps and no role layer at all. ADR-0006's principle — consume the authoritative source directly instead of hand-transcribing hex off a web page — is unchanged; what was wrong is an inference drawn from it, recorded in PRD §6.1 F6 and ROADMAP's M0 note, that the absence of role data in the package meant the question of per-palette roles was settled. It was not settled, it was published elsewhere, and nobody had looked there for four months ([ADR-0018](docs/adr/0018-chart-color-roles-follow-the-guidebook-role-layer.md)). Issue #122 and `docs/spikes/guidebook-color-roles.md` were themselves wrong about what the defect was, and this corrects them too: both claimed `secondary` drawing from the primary's own ramp was the structural error, when the guidebook's Primary _is_ a six-step ramp whose second step the official Power BI template paints category 2 with. The genuinely mis-mapped field was `accent` — which had been the guidebook's Secondary all along, hard-coded to Yellow across every palette. One word carried two meanings, a guidebook role name and a ramp-position name, in the same codebase and the same documents; that collision propagated a wrong finding into five records, so the rename is the fix for the mechanism rather than tidying. Roles are now `primary` / `primaryAlt` / `secondary` / `neutral`: `secondary` is per-palette (Cyan takes Green, Green takes Cyan, the other five Yellow, verified against all seven official 3840×2160 reference images rather than inferred); `neutral` is new and typed `string | null`, with `null` as the sanctioned absence for `guidebook-neutral` alone — the one palette the guidebook gives no Neutral row — gated by a single predicate derived from the role table so that a bug-produced `undefined` still fails loudly; steps are named by number and never by ramp position, since Blue's ramp starts at 1200 and SolidGray's at 900 and an index would have moved `guidebook-neutral`'s light primary from `#1a1a1a` to `#4d4d4d`; and `stepColor` looks a step up exactly, falling back to `nearestStep` only on a miss, without which "nearestStep is now just a drift fallback" was a comment the code did not implement and the off-ramp bug class this change fixes was still live. Six of forty-two resolved values change and the golden diff is exactly those six substitutions. `PRIMARY_ALT_STEP_OVERRIDE` (was `SECONDARY_STEP_OVERRIDE`) survives, and both prior explanations of it were wrong in opposite directions — it is not a guidebook-sanctioned exception, and it is not an artifact a corrected model removes; measured, the guidebook's own Cyan 600 is 2.83:1 against this background, so the published assignment fails the guidebook's own floor and hyakkei chooses the floor. `guidebook-cyan` gains two role collisions (`secondary == success`, because the guidebook paints Secondary 800 and Success as the same swatch), accepted with the decision written into ADR-0018 and a dated note on ADR-0009 _before_ the allowlist entries rather than appended after a red test. Verification needed building before the change could be observed at all: no snapshot in the repository baked `color[1]` or `color[2]` for any palette except orange, and `#666666` appeared zero times repo-wide, so "no golden diff" would have proven nothing — a three-slice pie fixture for all 7 × 2 combinations was therefore committed first (`d4aa066`) and baked against the _old_ role model, an ordering CI cannot enforce and which consequently lives in the history. Seven mutants were run and all are killed; three of them survived initially and the tests that kill them were written in response. Records corrected alongside the code, since a wrong record is what caused this: the spike, ADR-0006, ADR-0009, ADR-0016 (whose own read-forward note had replaced one wrong explanation with another), ADR-0017, PRD, ROADMAP, README, and `guidebook-coverage.md` — where the color-role row moves from _defect_ to _by construction_, taking the guaranteed count from 7 to 8 and known defects from 3 to 2. Deferred with reasons and filed: per-palette Error for Orange/Red (#127, reopens ADR-0009's palette-independence invariant), Positive/Negative (#128, Cyan's Positive has no step meeting 3:1 at all), the `Cyan 50` upstream divergence (#129), and artifact provenance (#130).
