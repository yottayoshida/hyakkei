# Changelog

Day-by-day development log for hyakkei, from repository bootstrap through the current M1 milestone. Each entry summarizes the PRs merged that day — what changed and why, not a line-by-line diff. See individual PR descriptions and ADRs under `docs/adr/` for full detail.

This project has not yet reached a versioned release; entries are grouped by date rather than by semver tag.

## 2026-07-22

- **feat(app): column type detection UI + manual override (issue #11b) (#98)** — Each registered column's semantic category (`text`/`number`/`date`) is now detected via Apache Arrow `typeId` guards (`arrowTypeCategory`, `packages/core/src/datasource/column-types.ts`, new) and shown in a native `<select>` per column, letting a user manually override it. An override triggers a real `TRY_CAST`-based validation query (uncastable count plus a few `{original, parsed}` interpretation samples) and refreshes the preview using DuckDB's actual cast result, never a client-side reformat. CAST target keywords only ever reach SQL through a closed `Record<ColumnCategory, string>` lookup (`castTargetFor`), which throws rather than degrading to `CAST(... AS undefined)` on any out-of-union value. `Source.typeOverrides` is added to the schema (delta-only, array-shaped, additive) — schema-contract only for this PR, since the app has no dashboard.json save/reload implementation yet. Two further diagnostics were added during review, orthogonal to the pass/fail cast outcome: a precision-loss advisory (a long integer-like id silently rounds past `DOUBLE`'s 53-bit exact range even though the cast "succeeds") and a timezone-offset-discarded advisory (`TRY_CAST(... AS DATE)` drops a UTC offset without normalizing to it first). `docs/adr/0011` records the design decisions and 5 accepted residual risks. Three separate verification passes each found and fixed a real defect only reproducible against live DuckDB-WASM execution, not static review: a `__proto__` prototype-pollution reintroduction in the preview-row merge, a conflated validation/preview failure path, a binder-time crash when a diagnostic query hit an already-native `DATE`/`TIMESTAMP` column (`regexp_matches`/`HUGEINT` casts require going through `CAST(col AS VARCHAR)` first), and a `HUGEINT` rounding-mode mismatch that false-flagged an ordinary decimal amount as precision-lossy.
- **feat(app): single-SPA editor integration, intake absorbed into index.html (issues #11a/#91/#42/#54 Stage B) (#95)** — `index.html` is now the product's single entry (ADR-0010): the intake ingestion UI is embedded directly into a new editor shell (`App.tsx`) instead of living behind a separate `intake.html` navigation, since DuckDB-WASM is in-memory/session-scoped and a page navigation would discard every registered table. Registration success now auto-enters a workspace (`sources[]` accumulate; no confirm click), sources can be added via a contained panel and deleted individually. Issue #91's data-layer chunk-load failure is now correctly attributed to the app's own code (not the user's file), with a reload affordance instead of the never-effective in-page retry — verified with a dedicated e2e test that reproduces the original warm-poisoning scenario via a synthetic aborted asset request. Issue #42's legacy `.xls` files are rejected with actionable re-save-as-`.xlsx` guidance instead of the generic unsupported-format copy. Issue #54's bundle-isolation contract (entry chunk must not statically contain DuckDB-WASM/exceljs/iconv) is re-verified for the editor entry via Vite's own build manifest (`dynamicImports`/`imports` graph) instead of chunk-text grepping, which two independent review rounds found could produce false negatives against this exact build. `intake.html`/`intake-main.tsx` retired. A WebKit-specific engine quirk was discovered and documented (ADR-0010 RR-1): WebKit does not re-fetch a dynamically-imported chunk whose earlier request was aborted, even across a full page reload, unlike Chromium/Firefox — one e2e assertion is scoped around this with a `test.skip`.

## 2026-07-17

- **fix(core): contain per-tile/resize failures and add a dashboard error boundary (issues #69/#68) (#93)** — `mount.ts` gained a per-tile `try/catch` (`renderTileSafely`) so one chart's throw degrades only that tile, not the whole grid, plus a per-instance `try/catch` in the resize pass and a debounced `ResizeObserver` (WeakMap-tracked, disconnected on unmount) so a container resize re-measures every chart. `App.tsx` gained a React error boundary around `DashboardPreview` for whatever falls outside `mount()`'s own per-tile scope. Code review (10 finder angles + verification + a gap sweep) found two independent ECharts instance leaks, converged on by 4 independent review angles: a throw _after_ `echarts.init()` succeeds — inside `setOption()` or in the accessible-fallback builder — used to leave a live, DOM-unattached instance that `unmount()` could never find to dispose, leaking zrender timers/listeners for the page's lifetime; fixed by disposing at the point of failure, pinned by tests using ECharts' own `isDisposed()` API and verified with mutation testing.
- **feat(app): lazy-load the data layer behind a dynamic import boundary (issue #54 Stage A) (#92)** — `packages/app/src/data-layer.ts` (new) hides `@hyakkei/core/datasource` (DuckDB-WASM, exceljs, iconv-lite) and the DuckDB factory behind a `loadDataLayer()` dynamic `import()` singleton, so the intake entry chunk no longer statically bundles ~1.5MB of data-layer dependencies it doesn't need until a file/URL is actually submitted. `bundle-isolation.test.ts` redefined to assert the entry chunk's static absence and the lazy chunk's presence, discovering lazy chunks via a new dist/assets scan (they never appear in the HTML's script tags). Found and corrected an overstated design comment: unlike what was originally documented, a failed dynamic `import()` is permanently cached by the browser's own HTML module-map spec for the page's lifetime — resetting the JS-side promise does not trigger a retry-from-scratch on the next call, only a page reload does.

## 2026-07-16

- **fix(core): memoize theme resolution, degrade instead of crash on contrast drift, characterize the semantic color collisions (issues #60/#65)** — `resolveChartColors` now memoizes its 14 possible (palette, appearance) results (frozen, shared references) and no longer throws inside the render path when a color falls below the 3:1 graphic-contrast floor: it ships the color, records a frozen `ContrastWarning` (new `getContrastWarnings()` public API), and `console.warn`s once per combination — for a browser-complete product read in air-gapped networks, a blank dashboard is strictly worse than one slightly-degraded color. CI keeps the hard gate by calling `assertGraphicContrast` directly against all 14 real combinations. Hardened the palette/appearance lookups against `"__proto__"` (which the old truthy check resolved to `Object.prototype` and let through) and added load-time existence guards for the cross-palette token families (Yellow accent, dark-mode Green/Red semantic borrows, Semantic) so upstream token drift fails naming the actual missing family instead of crashing opaquely inside `nearestStep` — deliberately family-existence only: a missing _step_ inside a surviving family degrades via nearest-step fallback rather than blanking the page at load. Issue #60's three byte-identical primary/semantic collisions (red×light, red×dark, green×dark) are accepted, not overridden — semantic colors stay palette-independent per ADR-0009 (new), and a bidirectional characterization test pins exactly those three so any new collision, or a token bump resolving a known one, fails visibly.
- **fix(core): treat a legend position without `show` as intent to show (issue #61)** — `{ "legend": { "position": "right" } }` was schema-valid but silently rendered no legend: `legendOption` treated an omitted `show` as `false`, so the position had zero effect and the author got no feedback. The legend contract is now three-valued and fully pinned by tests: no legend object → hidden; explicit `show: false` → hidden (position or not); any property present with `show` omitted → shown. The inferred default is documented on the schema's `ChartOptions.legend` (dashboard.json is an external authoring/MCP contract). No schema shape change, no golden output change (the only legend-bearing fixture already sets `show: true`).
- **fix(ci,test): CI now runs the app's render path, and a committed `test.only` fails the build (issue #64)** — `forbidOnly: !!process.env.CI` added to both `playwright.config.ts` and `e2e/pixel-golden.config.ts`; the latter's Docker-based CI job needed `-e CI` added to its `docker run` invocation too, since a container doesn't inherit the host's `CI=true` unless explicitly passed (verified empirically both ways: unset host env stays unset in the container, `CI=true` is correctly forwarded, and a real `test.only` fails the run only when `CI` is set — matching what GitHub Actions' runner shell actually looks like). `e2e/scaffold.spec.ts` was a `page.setContent()` placeholder proving only that Playwright itself works — the exact gap that let the real-browser chart-collapse bug (grid rows unsized, detached-container `echarts.init`) pass the full 3-browser matrix once already. It now navigates to the real built app and pins expected counts (one chart tile, one ECharts SVG canvas, one a11y fallback table, zero error tiles) before checking a real `boundingBox()`, mirroring `e2e/golden-narrow-viewport.spec.ts`'s existing pattern. `App.test.tsx` gained an explicit render-smoke test (mount/unmount mock kept — real chart content stays core's own test surface and e2e's). A follow-up commit also raised the suite's global assertion timeout (5000ms → 10000ms) after 3 consecutive CI runs hit it intermittently on webkit's DuckDB-WASM-backed intake flows — a different specific test each time, the signature of CI resource contention rather than a deterministic bug.

## 2026-07-14

- **fix(lint,ci): close residual lint bypasses and CI gaps found in PR #78 re-review (#80)** — An independent re-review of the previous day's lint-hardening PR found 10 confirmed bypasses still open: `self.eval`/`window.Function` had no `.call`/`.apply`/`.bind`/`Reflect.apply` indirection coverage even though other sinks did; double-cast (`window as unknown as T`) and bracket-notation forms slipped past the eval/Function selectors; `DOMParser` and `Object.defineProperties` were missing receiver/computed-key forms their sibling rules already had; the DOM-sink glob excluded `e2e/**` and root config files despite a comment claiming otherwise; `react-hooks/exhaustive-deps` shipped at `warn` with no `--max-warnings`, so CI could not have caught the bug it was added to prevent; CI's concurrency group keyed on branch name instead of PR number, letting unrelated PRs cancel each other's runs. All fixed and verified with dedicated `eslint --stdin` probes.

## 2026-07-12

Six PRs landed the same day, closing out M1's remaining audit and golden-test work:

- **feat(core,app,e2e): PR-C golden-test infrastructure (issue #8/#9 acceptance) (#77)** — Added the golden-test layer: 3 realistic sample dashboards (CJK content, all 7 chart types) snapshot-tested across authoring and baked render paths, both appearances, all 7 guidebook palettes; a Docker-based pixel-diff layer; a real-browser narrow-viewport regression spec. Found and fixed a scatter chart that was rendering fully black (raw population values used unscaled as marker pixel diameter) and 5 correctness bugs in the SVG snapshot normalizer itself.
- **fix(core): deny-all egress hint + response-size ceiling in fetchBytes (#74)** — `fetchBytes` now enforces a byte ceiling (default 256 MiB, content-length fast-fail plus streamed count) instead of an unbounded allocation; fixed a false-positive hint that misattributed a deny-all (no `selfOrigin` configured) rejection to an http-served-editor mismatch.
- **fix(schema,core): bake() duplicate-id safety, LayoutItem bounds, baked encoding cross-check (#75)** — `bake()`'s unconfigured-chart skip was array-position-based, not id-keyed, so a configured chart sharing an id with an unconfigured one could be silently dropped; fixed, plus a float-precision window in layout-overlap bounds checking and a new baked-vs-rows encoding cross-check.
- **fix(app,core): unmount-safe preview cleanup, finite-number normalization, `__proto__`-safe options record (#76)** — The preview component's unmount cleanup was reading `containerRef.current` _after_ React nulls host refs on unmount, silently skipping ECharts disposal on every unmount — the exact case the cleanup existed for. Fixed by closing over the mounted element instead. Also: NaN/Infinity now normalize consistently between the authoring preview and the baked (JSON round-tripped) viewer, and a `__proto__` chart id no longer vanishes from the options record.
- **fix(core,schema): golden sample JSON canonicalization + round-trip validation (issue #6/#10) (#79)** — Found that all 3 golden samples declared `sources: []` while their queries referenced undeclared source ids — 8 dangling references invisible to the existing tests because none of them called schema validation. Rewrote the SQL to valid queries against declared sources and added a round-trip test chaining `parseDashboard → reference validation → SQL fixture-lint → bake() → parseBakedDashboard → baked reference validation` for all 3 samples in one pass.
- **fix(lint,ci): widen XSS-sink lint coverage, enable react-hooks, dedupe CI builds (#78)** — The innerHTML/outerHTML/insertAdjacentHTML ban only covered `packages/core`'s `.ts` files, missing `packages/app`, `packages/export`, and every `.tsx` file; `react-hooks` lint rules were never installed despite `packages/app` being a real React codebase (issue #55's ref-read-in-cleanup bug is exactly what `exhaustive-deps` would have caught). Widened coverage to every package and added `document.write`/`DOMParser`/`createContextualFragment`/`eval`/`Function` sink detection across static, computed-string, and computed-template-literal call forms. CI also stopped building every package three times per run.

- **feat(core): renderer core and bake() (issue #8 PR-B) (#52)** — Introduced the shared `bake()` transform (authoring document → frozen `BakedDashboard`) and the renderer core both the editor preview and the export path consume. First real-browser verification caught a chart rendering as a collapsed ~200×100 box — three compounding causes invisible to jsdom (which does no real layout): missing grid row sizing, a `height:100%` canvas against an auto-height parent, and `echarts.init()` running before the container was attached to the DOM.

## 2026-07-08

- **feat(schema,core): DataSource contract layer and EgressPolicy (issue #7 PR-A1) (#49)** — Established the `DataSource`/`RegisterContext`/`EgressPolicy` interface (table-registrar shape, not query-executor — keeps a future v1.0 `ProxySource` additive rather than a redesign) and implemented `createEgressPolicy`: a same-origin-only network chokepoint that re-derives safety from the _resolved_ URL rather than trusting the input string, defeating userinfo host-spoofing, mixed-case scheme, and protocol-relative payload attacks. `Source.id`/`Query.source` restricted to a safe SQL-identifier pattern with case-insensitive duplicate detection (DuckDB identifier lookups are always case-insensitive). Scope deliberately limited to the contract + egress policy; FileSource/UrlSource ingestion and the intake UI were left for later PRs.

## 2026-07-07

- **feat(schema): implement dashboard.json + BakedDashboard JSON Schema v1 (#47)** — Implemented the authoring `dashboard.json` and exported `BakedDashboard` schemas using TypeBox+Ajv as a single source of truth for JSON Schema and TS types. Encoded two security-critical constraints: theme tokens/palette as closed enum allowlists, and `chart.options` as a closed declarative allowlist with no ECharts passthrough (an XSS vector otherwise). Found and fixed a live exploit during review: `rows`' `Type.Record` had no `propertyNames` guard, letting a `'__proto__'` row key through and letting newline-containing keys bypass value-type validation entirely.
